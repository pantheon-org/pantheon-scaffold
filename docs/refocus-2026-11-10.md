# Refocus of 10-11-2026

On 10-11-2026 the owner refocused the repository on one job: define the GitHub CI/CD of the `pantheon-*` repositories in pkl and render it from one `pantheon.pkl` per repository. This page records what changed and why, so the history of the earlier decisions stays readable.

## The charter

- Any GitHub workflow a repository needs is ported into the package as a Builtin, whatever language the repository uses.
- A **Preset** is a local custom version of a Builtin, which a repository uses to add to or override it.
- The runner is a Rust project built with TDD, BDD (cucumber-rs) and mutation testing (cargo-mutants).
- `init` sets up a new project, and `migrate` brings an existing project under the scaffold.
- The first pass covers `pantheon-adr`, `pantheon-journal`, `pantheon-skill-auditor` and `pantheon-agentic-harness-dev-kit`. Only the `rust` ecosystem value is built. `tekhne` and this repository follow later, once the dry-run results for the four repositories are recorded.

## Decisions reversed or amended

These were recorded in the plans of 06-11-2026 and 09-11-2026. They are not rewritten there; this page is the dated record of the change.

| Earlier decision | Was | Now |
|---|---|---|
| N1 (09-11-2026) | The runner is rewritten in Rust only after dog-food and `init`, behind a go or no-go gate: no-go if the estimate is above 4 weeks of focused work, or if the YAML parser cannot match the equality rule. | The runner is rewritten in Rust. The 4-week gate is dropped. A checkpoint after the pkl, schema, `render` and `check` slice has pass criteria only and no time box. The TypeScript runner is removed only after one release cycle of Rust use. |
| N2 (09-11-2026) | pklr is a gated goal; the Rust runner starts on the pkl binary. | Unchanged in effect: the runner reads pkl through the pinned pkl binary, and pklr stays out of scope. |
| N6 (09-11-2026) | `init` writes `pantheon.pkl` once and only `upgrade` edits it afterwards. No `add` or `remove` commands, no Presets, no TUI. Custom builtins are shared as a separate package. The plan gave no reason beyond keeping the scope small. | Presets are in scope, as local custom versions of a Builtin. `add`, `remove` and a TUI stay out. Why it is reversed: the owner wants repositories to define local versions that add to or override Builtins. |

## What was dropped

- **Governance** (the desired rulesets, the merge settings task and the weekly drift workflow). Nothing was ever applied to a real repository. The code and its notes are archived, and ruleset drift is no longer checked. Revisit when governance returns to scope.
- pklr, Windows, GitLab and `self-update` stay out, as before.

## What was archived

The spike and proof evidence (the former `tmp/` folders, the proof and dossier documents and their scripts) and the governance code now live under `archive/`, with an index in [archive/README.md](../archive/README.md). The state before the move is the tag `pre-refocus`. The runner files that stay, move to Rust or are re-pointed are sorted in [runner-file-sort.md](runner-file-sort.md).
